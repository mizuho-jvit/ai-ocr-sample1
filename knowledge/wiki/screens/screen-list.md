# 画面一覧

> 正典化元: 要件定義書 v1.8 §6（原本は `knowledge/ref/doc/claude_code_要件定義_v1.8.md`）
> UI の実体はプロトタイプ `knowledge/ref/doc/ai-ocr-demo.jsx`。デザイン要件は [プロジェクト概要](../requirements/overview.md#デザイン要件)。

**すべての画面・静的アセット・APIは最初にBasic認証を必要とし、その後すべての画面でアプリ内ログインを必要とする。** Basic認証はadmin / staff の識別やロール認可を代替しない（F-1-11〜15）。

| 画面 | ロール | 主な要件 |
|---|---|---|
| ログイン | — | 失敗ロック、エラー文言の統一（F-1-6, F-1-7）。**テナントコード入力欄は設けない** |
| ホーム（アップロード＋台帳） | admin / staff | プロトタイプUIを移植。**当月の残り読取可能枚数を表示する**（NF-2-18。商談中に予告なく上限へ到達することを防ぐ） |
| 読取確認 | admin / staff | 原本画像との並列表示。確信度85%未満を黄色でハイライトし「OK」ボタンを表示。全項目を直接修正可能とし、修正履歴を保持。「業務チェックへ進む」で申請詳細へ遷移する |
| 申請状況一覧 | admin / staff | AI判定・処理状態・処理者・紐付け有無でフィルタ。「要審査のみ」ビュー |
| 申請詳細 | admin / staff | 原本画像閲覧、項目編集、ステータス変更、業務チェック再実施（整合性・不備・名寄せ・トリアージ・差戻し文面を表示。名寄せは候補カードUI=F-6-7）、会員紐付け、差戻し文面の再表示・編集・クリップボードへのコピー（編集内容は保存しない。[決定#34](../requirements/decisions.md)）。**独立した「業務チェック結果」画面は作らず、この画面へ統合する**（名寄せ判断APIが`/api/applications/:id/match-candidates/*`に置かれているため。[決定#2](../requirements/decisions.md)） |
| 会員一覧・検索 | admin / staff | 表記ゆれ検索、状態フィルタ |
| 会員詳細 | admin / staff | 申請履歴、状態遷移履歴、状態変更 |
| 重複疑いリスト | admin / staff | 未解決の名寄せ候補一覧 |
| スタッフ管理 | admin のみ | スタッフの登録・編集・無効化 |
| デモデータ初期化 | admin のみ | 削除対象の件数表示、確認語の入力、実行結果の表示（F-9）。`ALLOW_DATA_RESET` 未設定時はメニューに表示しない |

## 画面上に常時表示する注記

営業戦略に直結するため、**機能追加・改修時も失わないこと**（[プロダクトポジショニング](../requirements/overview.md#プロダクトポジショニング設計ui文言の制約)）。

- 「最終判断は必ず職員が行う」
- 「AIが申請者へ直接連絡することはない」
- AIの確信度は「目安」であり統計的な精度保証ではない旨

## 商談で見せる動線

**OCR読取 → 業務チェック → 名寄せ → 承認**のみを提示する。**会員の編集・状態変更は見せない。** この方針が F-9 でシード会員の値を復元しない根拠になっている（[復元しない根拠](../requirements/functional.md#シード会員の値を復元しない根拠)）。
