## 要求ドキュメントからの変更点

| # | 要求 § | 変更内容 | 理由 |
|---|---|---|---|
| 1 | §5 | Next.js → **Vite + React SPA + Hono** | 無料枠のバンドルサイズ制限。またプロトタイプがSPAのため移植が容易 |
| 2 | §5 | SQLite（ファイル）+ Prisma → **D1 + Drizzle** | Workers に永続FSが無い。Prisma はバンドルが重い |
| 3 | §5 | `/uploads` ローカル保存 → **R2** | 同上 |

| 5 | §3 | AIモデル `claude-sonnet-4-6` → **Gemini 3.1 Flash Lite** | 日本語手書きOCRのベンチマーク結果（[選定根拠](../architecture/ai-api.md#選定根拠)） |

| 9 | §6 | `MatchCandidate` に UNIQUE(applicationId, memberId) を追加 | 再実施時の重複登録防止 |
| 10 | §10 | マルチテナント → **クエリのテナント条件は実装する**（[テナント分離](./tenant-isolation.md)）。**テナントは設定固定の1件**とし、識別・切替は対象外 | 後から全クエリへ条件を追加すると漏れを検出できないため条件は初めから入れる。一方テナント切替はMVPに不要で、供給源を1関数に閉じれば後から差し替えられる |
| 11 | §10 | `orgId` → **`tenantId`** に名称統一 | 同一概念を2つの名前で呼ばない（[用語](./tenant-isolation.md#用語)） |
| 12 | — | **F-9 デモデータのリセットを新設** | 単一環境を全商談で共用するため、商談ごとに初期状態へ戻す手段が必要（[運用要件](./operations.md)・下記 #8） |

## 撤回した判断

要件定義の過程で一度採用し、後に取り下げた論拠。**同じ結論を再導出しようとした際に、成立しない前提を再利用しないための記録である。**

| 撤回した記述 | 撤回した時期 | 理由 |
|---|---|---|
| 顧客ごとに環境を払い出し、環境分離を「コードの正しさに依存しない最後の防御層」とする（第4層） | v1.4 | MVP はデモとしてのみ使用し、顧客へ環境を引き渡さないため。分離すべき顧客データが存在しない。帰結として[第4層は存在しない](./tenant-isolation.md#第4層-運用上のデータ同居を避ける-採用しない) |
| `UNIQUE(tenantId, memberNumber)` は「今しか設定できない」（複数環境の統合時に `memberNumber` が全件衝突するため） | v1.4 | 上記により統合すべき別環境が存在しなくなった。制約自体は妥当だが緊急性はない（[スキーマ側を今確定させる理由](./tenant-isolation.md#スキーマ側を今確定させる理由)） |
| リセット時にシード会員の値を復元する処理が必要（承認操作で `status` が `pending → active` に変わるため） | v1.4 | プロトタイプ `SEED_MEMBERS` を確認したところ**シード会員は5件とも `status: "active"` で投入されており**、F-4-3 の `pending` 条件が発火しない。加えて商談で会員管理を提示しない方針が確定した（[復元しない根拠](./functional.md#シード会員の値を復元しない根拠)） |
| `orgId` という列名（要求ドキュメント由来） | v1.3 | 同一概念を2つの名前で定義すると識別できなくなるため `tenantId` に統一 |
