# 非機能要件（性能・セキュリティ・データ保持・保守性）

> 正典化元: 要件定義書 v1.11 §7.1〜§7.4（原本は `knowledge/ref/doc/claude_code_要件定義_v1.11.md`）
> テナント分離（§7.5）は分量が大きいため [テナント分離](./tenant-isolation.md) に分離した。

## 性能

| ID | 要件 |
|---|---|
| NF-1-1 | OCR読取（F-2）の応答時間は、**MVP 1.0で15秒以内、MVP 1.1で20秒以内**を目標とする（1.0の参考値: Gemini 3.1 Flash Lite の実測 約13.7秒）。1.1はDocument AIとGeminiの逐次呼び出しを含むため、実装後に実測して妥当性を再確認する |
| NF-1-2 | AI業務チェック（F-3）の応答時間は **10秒以内**を目標とする |
| NF-1-3 | 上記以外の画面遷移・一覧表示は 1秒以内を目標とする |
| NF-1-4 | 待機中は進捗表示を行い、処理中であることを明示する |

## セキュリティ

### パスワード管理

| ID | 要件 |
|---|---|
| NF-2-1 | パスワードは **PBKDF2-SHA256（WebCrypto）** でハッシュ化する。Workers 環境ではネイティブモジュールが使用できないため、bcrypt / argon2 は採用しない |
| NF-2-2 | ハッシュは**アルゴリズム・反復回数・ソルトを含む自己記述形式**で保存する<br>`pbkdf2-sha256$<iterations>$<salt-base64>$<hash-base64>` |
| NF-2-3 | 検証時は**保存された反復回数**を用いて再計算する。これにより既定値を変更しても既存アカウントの認証は継続して成功する |
| NF-2-4 | ソルトはアカウントごとにランダム生成する（16バイト以上） |
| NF-2-5 | 反復回数は環境変数 `PBKDF2_ITERATIONS` で指定する。**デフォルト値を持たず、未設定時は起動を失敗させる** |
| NF-2-6 | `PBKDF2_ITERATIONS` が 100,000 未満の場合、環境変数 `ALLOW_WEAK_PASSWORD_HASH=true` が明示的に設定されていなければ起動を失敗させる |
| NF-2-7 | **デモ環境では `PBKDF2_ITERATIONS=20000` および `ALLOW_WEAK_PASSWORD_HASH=true` を設定する。** 20,000回は Workers 無料枠のCPU時間制約（10ms／リクエスト）との両立を前提とする暫定値であり、実装後にリモート環境で認証処理全体のCPU時間を検証する。**暗号強度は本番水準にない** |
| NF-2-8 | 実案件へ移行する際は `PBKDF2_ITERATIONS` を 600,000 以上に設定するか、argon2id 相当へ切り替えること。NF-2-2 の保存形式により、既存データを破壊せず移行できる |
| NF-2-9 | ログイン成功時、保存された反復回数が現在の既定値を下回る場合はハッシュを再生成してDBを更新する（opportunistic rehash） |

### アクセス制御・その他

| ID | 要件 |
|---|---|
| NF-2-10 | 未ログイン状態では全画面・全APIにアクセスできないこと。API直接呼び出しでも 401 を返す |
| NF-2-11 | staff ロールが admin 専用APIを呼び出した場合、403 を返す |
| NF-2-12 | 会員（一般ユーザー）側には認証情報・ログイン手段が一切存在しないこと |
| NF-2-13 | **AI APIキーはサーバーサイドのみで保持する。** フロントエンドのバンドルおよびネットワーク通信に一切露出させない |
| NF-2-14 | 原本画像は R2 に保存し、**署名付きURL経由でのみ配信する**（有効期限15分）。直接URLでのアクセスを不可とする |
| NF-2-15 | **AI Gateway に予算上限を設定する。** 常設公開URLのため、悪意ある大量リクエストによる従量課金の暴走を防ぐ。プロセス外の最終防衛線として位置づけ、**一次的な歯止めはアプリケーション側の月次上限（NF-2-18・NF-2-34）とする。** 予算上限は全プランで利用可だが公開ベータであるため、これ単独に依存しない |
| NF-2-16 | **上限に到達した場合、AI呼び出しを実行せずエラーを返す**（fail closed）。上限を超えて処理を継続してはならない |
| NF-2-17 | 上限は Pass①（読取）・Pass②（業務チェック）の**両方を合算した消費額**に対して適用する。片方のみを対象としない |
| NF-2-23 | Basic認証の資格情報は環境ごとのWorkers Secret `BASIC_AUTH_USERNAME` / `BASIC_AUTH_PASSWORD` として保存する。平文の `vars`、`wrangler.toml`、Git追跡ファイル、D1には保存しない |
| NF-2-24 | `BASIC_AUTH_USERNAME` / `BASIC_AUTH_PASSWORD` はデフォルト値を持たず、いずれかが未設定の場合は起動を失敗させる |
| NF-2-25 | Basic認証はHTTPSでのみ使用する。`*.workers.dev` のHTTPS URLを使用し、平文HTTPで資格情報を送信しない |
| NF-2-26 | `Authorization` ヘッダおよびBasic認証の資格情報をアプリケーションログ、AI Gateway、エラー応答へ出力しない |
| NF-2-27 | Workers Static Assetsに `binding = "ASSETS"` と `run_worker_first = true` を設定し、`index.html`、JavaScript、CSS、画像等がBasic認証を迂回して直接配信されないようにする |
| NF-2-28 | Basic認証に成功してもアプリ内セッションがなければ、保護対象APIは従来どおりアプリ内認証の `401` を返す。Basic認証だけで業務データへアクセスさせない |
| NF-2-29 | MVP 1.1のDocument AI認証には専用サービスアカウントを使用する。サービスアカウントのメールアドレスと秘密鍵はWorkers側だけで扱い、秘密鍵はWorkers Secret `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` に保存する。フロントエンド、D1、R2、ログへ出力・保存しない |
| NF-2-30 | MVP 1.1のサービスアカウントには、対象Processorに対するDocument AI API User（`roles/documentai.apiUser`）だけを付与し、Owner・Editor等の広いロールを付与しない |
| NF-2-31 | Document AIのOAuthアクセストークンはメモリ上でのみ扱い、ログ・D1・R2へ保存しない。期限切れ時に再取得する |
| NF-2-32 | Document AIのリクエスト・レスポンス、OCR全文、元画像をアプリケーションログおよびAI Gatewayログへ出力しない |
| NF-2-33 | Document AIの利用料はCloudflare AI Gatewayの予算上限では制御できない。MVP 1.1でも `MAX_OCR_PAGES_PER_MONTH` をDocument AI呼び出し前に検証し、Google Cloud Billingの予算アラートを併用する。予算アラートは自動停止ではないことを運用上の前提とする |
| NF-2-42 | **AI Gateway のペイロードログ収集を無効化する。** AI Gateway はリクエスト・レスポンスの**本文を既定で保存する**ため、無効化しない限り帳票の元画像とOCR全文がCloudflare側へ保存される。`cf-aig-collect-log-payload: false` ヘッダの付与、またはゲートウェイ設定で明示的に切る。**NF-2-32 を満たすための具体手段であり、既定値に依存しない** |
| NF-2-43 | **ペイロードを止める一方で、ログのメタデータ収集は維持する**（トークン数・モデル・プロバイダ・ステータスコード・費用・所要時間）。`cf-aig-collect-log: false` でエントリ全体を止めない。[コスト試算](../architecture/ai-cost-simulation.md)で保留している実トークン数の計測に必要である |
| NF-2-44 | **AI Gateway の Guardrails を使用しない。** Guardrails は判定モデル（`@cf/meta/llama-guard-3-8b`）をWorkers AIのトークン推論として課金するため、BYOK構成に不要な課金経路を持ち込む。入出力の検査はGeminiのStructured Outputsとアプリケーション側の検証で行う |
| NF-2-45 | **ゲートウェイの「Workers AI 課金」設定は「標準課金」を選択する。** 「統合課金」はAI Gatewayのクレジット残高からリアルタイムに引き落とす方式で、クレジットに対し5%の手数料が発生する。BYOK（自前のGemini APIキー）構成では不要である |

### AI呼び出し回数の上限（アプリケーション側）

NF-2-15 は Cloudflare 側の最終的な歯止めであり、到達した時点で既に課金が発生している。**課金が発生する前にアプリケーション側で止める**ため、以下の上限を設ける。上限は**月次**で管理する。

#### 上限値の定義

| ID | 要件 |
|---|---|
| NF-2-18 | **月間の読取枚数に上限を設ける。** 上限は環境変数 `MAX_OCR_PAGES_PER_MONTH` で指定し、**MVP では 120 を設定する**。デフォルト値を持たせず、**未設定の場合は起動を失敗させる**（未設定が「無制限」として動作することを防ぐ） |
| NF-2-34 | **月間のGemini呼び出し回数にも上限を設ける。** 環境変数 `MAX_GEMINI_CALLS_PER_MONTH` で指定し、**MVP では 720 を設定する**。Pass①・Pass②を**合算**して計上し、NF-2-17 を月次カウンタで満たす。未設定時は起動を失敗させる |
| NF-2-21 | **業務チェック（Pass②）の再実施回数にも上限を設ける。** 1申請あたりの `CheckRun` 件数を環境変数 `MAX_CHECK_RUNS_PER_APPLICATION` で制限し、**MVP では 5 を設定する**。NF-2-18 と同様、未設定時は起動を失敗させる |
| NF-2-35 | **上限値は 1 以上の整数として検証する。** 非数値・0・負値・小数は起動を失敗させる（不正値が「無制限」または「常に上限到達」として動作することを防ぐ） |
| NF-2-36 | **上限値をコードへハードコードしない。** 変更は環境変数の値の書き換えと再デプロイのみで完結し、**スキーマ変更・コード修正・データ移行を要しないこと。** 上限値を参照する箇所は1つのモジュールへ集約する |
| NF-2-38 | **上限値をリクエスト単位・画面単位で上書きする手段を設けない。** クエリパラメータ・ヘッダ・管理画面からの変更手段を実装しない（`OCR_PIPELINE_MODE` と同じ扱い） |

> `MAX_GEMINI_CALLS_PER_MONTH=720` は他の2つの上限から導かれる最悪値（読取120回＋業務チェック 120×5＝600回）と一致する。したがって通常運用では発動せず、**申請単位の上限（NF-2-21）が機能しなかった場合にのみ作動する不変条件チェック**として働く。

#### カウンタの実装

| ID | 要件 |
|---|---|
| NF-2-19 | **専用のカウンタテーブル `UsageCounter` を設ける。** 期間キー `YYYY-MM`（**JST**）を主キーとし、読取枚数とGemini呼び出し回数を保持する。**保存されている期間キーが現在の期間キーと一致しない場合は 0 として扱い、現在の期間キーで上書きする**（日付を判定する明示的なリセット処理を持たない） |
| NF-2-39 | カウンタの加算は**単一の条件付き UPDATE**（`WHERE period = ? AND ocrPages < ?` のように上限判定を UPDATE 文に含める）で行い、**影響行数 0 を上限到達として扱う**。読み取ってから判定し別途更新する実装にしない（同時リクエストによる上限超過を防ぐため）。加算は AI 呼び出しの**前**に実施する |
| NF-2-40 | **F-9（デモデータのリセット）は `UsageCounter` を初期化しない。** 初期化できると上限を回避できてしまうため |
| NF-2-41 | `UsageCounter` は**テナント横断のグローバル**で保持し、`tenantId` で分割しない（Document AIの無料枠がGoogle Cloudプロジェクト単位であるため） |
| NF-2-37 | **上限値を引き下げた場合、当月の既存消費量が新しい上限を超えていれば、その月は即 fail closed とする。** 引き下げが遡って有効になることを許容する（安全側に倒す） |
| NF-2-20 | 上限到達時は**AI呼び出しを実行せず**、上限に達した旨と、**翌月まで待つか `MAX_OCR_PAGES_PER_MONTH` の引き上げ（再デプロイ）が必要である旨**を画面に表示する。**F-9 のリセットでは解除されない** |
| NF-2-22 | セッション単位の実行回数制限は設けない。上限は月間の累計に対して適用する |

> **Pass② にも上限が必要な理由**: 業務チェックの再実施（F-4-6）は画像を伴わないが**約0.19円/回の課金が発生し、同一申請に対して何度でも実行できる。** 読取枚数のみを制限しても、再実施を繰り返すことで上限を回避して費用が伸びる。
>
> **想定される最大費用**: 読取 120枚 × 約0.26円 ＋ 業務チェック 120件 × 5回 × 約0.19円 ＝ **約145円／月**。想定運用（各申請で業務チェック1回）では**約54円／月**に収まる（[AI API利用料シミュレーション](../architecture/ai-cost-simulation.md#月次シミュレーション)）。
>
> **累計から月次へ変更した理由**: MVP 1.1 のDocument AI無料枠（月1,000ページ）が**月単位**であり、保護対象と判定単位を一致させる必要がある。累計上限＋F-9 のリセットでは、リセットを繰り返すことで月内に無料枠を超過し得た。
>
> **専用カウンタテーブルを設ける理由**: `Application` の件数を判定値にすると、F-9 のリセットで枠が戻ってしまい月次上限として機能しない。またPass②の呼び出し回数は `Application` の件数では表せない。**F-9 でリセットされない独立したカウンタが必要である**（NF-2-40）。
>
> **セッション単位にしない理由**: 認証済み利用者は再ログインで解除できるため実効性がなく、デモの動線（複数の帳票を続けて読み取りAI判定の違いを見せる）を阻害する副作用のみが残る。月間の累計で制限すれば、連続した読取を妨げずに総額を抑えられる。
>
> **期間キーの時間帯**: 期間キーは JST で判定する。Google Cloud の請求月および無料枠のリセットとは完全には一致しないため、上限値を無料枠より十分低く設定してマージンで吸収する（読取120枚に対しDocument AI無料枠は月1,000ページ）。
>
> **限界**: 加算を条件付き UPDATE で原子的に行うため、同時リクエストによる上限超過は発生しない。ただし**加算をAI呼び出しの前に行うため、AI呼び出しが失敗した試行も枠を消費する**（fail closed 側に倒す判断）。上限値の変更には再デプロイが必要であり、稼働中の無停止変更はできない。最終的な歯止めは NF-2-15 が担う（多層防御）。

## データ保持

| ID | 要件 |
|---|---|
| NF-3-1 | 原本画像の保持期間は **30日**とし、経過後は削除する |
| NF-3-2 | 申請詳細画面から原本画像を個別に削除できること |
| NF-3-3 | 顧客の実データ（実在の個人情報）を投入しないことを運用前提とする。README に明記する |

> 単一環境を全商談で共用するため、NF-3-3 の重要性は環境分離時より高い（OP-9）。[運用要件](./operations.md#共用に伴う運用上の帰結)を参照。

## 保守性

| ID | 要件 |
|---|---|
| NF-4-1 | **DBアクセスはリポジトリ層に集約し、ハンドラや画面から直接クエリを記述しない**（テナント条件の付与を1箇所に閉じ込めるため。[テナント分離](./tenant-isolation.md)） |
| NF-4-2 | 外部OCR・AI APIの呼び出しをOCR Pipeline境界へ集約する。ハンドラからGeminiまたはDocument AIを直接呼び出さず、`OCR_PIPELINE_MODE` に対応する実装を差し替え可能とする（[外部AI API](../architecture/ai-api.md#実装設計)） |
| NF-4-3 | 審査ルール・確信度閾値・名寄せスコアリングの重みは定数として一元管理し、ロジック内に散在させない。**確信度閾値は 85% とする（定数。環境変数による変更は行わない）** |
| NF-4-4 | 旧字体・異体字対応表はJSONファイルとしてアプリケーションに同梱し、Gitで変更履歴を管理する。実行時のDB問い合わせは行わない。テナント別編集、管理画面からの即時反映、または対応表の大規模化が必要になった時点でDB化を再検討する |
| NF-4-5 | `OCR_PIPELINE_MODE` は `gemini`（MVP 1.0）または `document-ai-gemini`（MVP 1.1）のみを許可し、未設定・未知の値では起動を失敗させる。画面やリクエスト単位で変更させない |
| NF-4-6 | GeminiのモデルIDは `GEMINI_MODEL` で設定し、コードへハードコードしない。MVP 1.0・1.1ともPass①とPass②の既定値は `gemini-3.1-flash-lite` とする |
| NF-4-7 | `document-ai-gemini` の場合、Google Cloudプロジェクト、ロケーション、Processor ID、サービスアカウント情報が1件でも未設定なら起動を失敗させる。`gemini` の場合はDocument AI固有設定を要求しない |

## 環境変数の一覧（統合）

各要件に散在している環境変数・Secretを1箇所にまとめたもの。未設定または条件未充足で起動失敗する項目が複数あるため、開発者は本表を参照して `.dev.vars` を作成する（[README](../../../README.md#セットアップと開発)）。秘密値の実際の値は本表・READMEのいずれにも書かない。

| 環境変数 | MVP の値 | 未設定時 | 定義元 |
|---|---|---|---|
| `TENANT_ID` | シード投入した `Tenant.id` | **起動失敗** | NF-5-4・[テナント分離](./tenant-isolation.md#テナントidの解決) |
| `PBKDF2_ITERATIONS` | `20000` | **起動失敗** | NF-2-5・7 |
| `ALLOW_WEAK_PASSWORD_HASH` | `true` | 反復回数が10万未満なら**起動失敗** | NF-2-6 |
| `MAX_OCR_PAGES_PER_MONTH` | `120` | **起動失敗** | NF-2-18 |
| `MAX_GEMINI_CALLS_PER_MONTH` | `720` | **起動失敗** | NF-2-34 |
| `MAX_CHECK_RUNS_PER_APPLICATION` | `5` | **起動失敗** | NF-2-21 |
| `ALLOW_DATA_RESET` | `true` | F-9 の API が **404**（機能無効） | F-9-8 |
| `BASIC_AUTH_USERNAME` | デモ環境専用のユーザー名（Workers Secret） | **起動失敗** | NF-2-23・24 |
| `BASIC_AUTH_PASSWORD` | アプリ内認証と異なる20文字以上のランダム値（Workers Secret） | **起動失敗** | F-1-14・15、NF-2-23・24 |
| `OCR_PIPELINE_MODE` | 1.0: `gemini`／1.1: `document-ai-gemini` | **起動失敗** | NF-4-5 |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` | **起動失敗** | NF-4-6 |
| `GEMINI_API_KEY` | Gemini APIキー（Workers Secret） | **起動失敗** | NF-2-13 |
| `R2_ACCOUNT_ID` | R2 S3 APIのCloudflare Account ID | **起動失敗** | NF-2-14・判断記録 #18 |
| `R2_S3_ACCESS_KEY_ID` | 署名URL発行専用のR2 S3 API Access Key ID（Workers Secret） | **起動失敗** | NF-2-14・判断記録 #18 |
| `R2_S3_SECRET_ACCESS_KEY` | 署名URL発行専用のR2 S3 API Secret Access Key（Workers Secret） | **起動失敗** | NF-2-14・判断記録 #18 |
| `GOOGLE_CLOUD_PROJECT_ID` | 1.1のGoogle CloudプロジェクトID | 1.1のみ**起動失敗** | NF-4-7 |
| `DOCUMENT_AI_LOCATION` | 1.1のProcessorロケーション | 1.1のみ**起動失敗** | NF-4-7 |
| `DOCUMENT_AI_PROCESSOR_ID` | 1.1のEnterprise OCR Processor ID | 1.1のみ**起動失敗** | NF-4-7 |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | 1.1専用サービスアカウント | 1.1のみ**起動失敗** | NF-2-29・NF-4-7 |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | サービスアカウント秘密鍵（Workers Secret） | 1.1のみ**起動失敗** | NF-2-29・NF-4-7 |

起動時にはこれに加えて、`TENANT_ID` に対応する `Tenant` 行の存在（NF-5-5）と `Tenant` の行数が1件であること（NF-5-15）を検証する。
