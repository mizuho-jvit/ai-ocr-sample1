## Test Framework

| Item | Value |
|---|---|
| Framework | Vitest 4。`test.projects` で2プロジェクトに分割 |
| Config file | `vitest.config.ts`（`wrangler.toml`を参照） |
| `worker` project | `@cloudflare/vitest-pool-workers`（workerd上）。対象は `test/worker/**/*.test.ts` |
| `react-app` project | `happy-dom` + `@testing-library/react`。対象は `test/react-app/**/*.test.{ts,tsx}`。setup は `test/react-app/test-setup.ts` |
| Test command | `corepack pnpm test` |
| Single test | `corepack pnpm test -- test/worker/index.test.ts` |
| Single project | `corepack pnpm test -- --project react-app` |
| Coverage | 閾値は未設定（coverage provider も未導入） |

**プロジェクトを分ける理由:** `cloudflareTest()` を全体へ適用するとSPAのテストもworkerd上で動きDOMが無いため描画テストが書けない。逆にSPA側へworkerdプールを適用しない限り、WorkerテストのD1・R2バインディングは得られない。`include` はディレクトリで完全に分離する。

SPAからWorkerの型は `import type` でのみ共有する（`src/worker/types/contracts.ts`）。実行時コードはSPAへ持ち込まない。

**テストは `test/` へ分離し、`src/` と同じディレクトリ構成をミラーする**（AGENTS.mdの規約）。importグラフに乗らないためビルド成果物には元々含まれないが、本体とテストのディレクトリを分けて見通しやすくする。

WorkersテストはローカルポートとWranglerログへの書込みを必要とする。sandboxで失敗した場合は、権限昇格した実行環境で再実行する。

## Database

- スキーマ: `src/worker/db/schema.ts`
- テーブル: `tenants` / `staff_users` / `members` / `applications` / `check_runs` / `usage_counter` / `match_candidates` / `app_status_history` / `status_history` / `sessions`
- DB列・テーブル名は `snake_case`、TypeScriptプロパティは `camelCase` にマッピングする。
- `usage_counter` を除く全テーブルに `tenant_id` を持たせ、クエリではテナント条件を必ず付与する。
- 状態値は英字文字列コードを保存し、SQLite `CHECK` 制約とTypeScript型で値集合を制限する。日本語は画面・CSVでの表示ラベルに限定する。
- 初回マイグレーションはローカルD1へ適用済み。`wrangler.toml` のD1 IDはローカル用仮値なので、実ID設定前に `dev:remote` / `deploy` を実行しない。

### Naming

| Target | Convention | Example |
|---|---|---|

### Imports

外部依存 → 内部モジュール → 相対パスの順。named importを優先する。

### Errors and logging

- Worker起動時の必須設定はガード節で検証する。
- APIエラー形式と認可・入力検証は `knowledge/wiki/architecture/api.md` を正とし、将来Honoの `onError` で一元化する。
- 秘密値、Basic認証情報、AIペイロード、顧客データをログ・エラー応答に含めない。
- Workersでは `env` バインディングから設定を読む。`process.env` は使わない。

## Security and Deployment Boundaries

- Static Assetsは `dist/client/` のみ。`knowledge/` と `docs/` をWorkerへ配信・importしない。
- `assets.run_worker_first = true` を維持し、静的アセットがBasic認証を迂回しないようにする。
- 無料枠のWorker CPU時間は10ms/リクエスト。画像リサイズ（長辺1568px、JPEG品質85%）はクライアント側で行い、CPU時間は `dev:remote` またはデプロイ後に確認する。
- セッションはD1 + `HTTPOnly` / `Secure` / `SameSite=Lax` Cookie。JWTをlocalStorageへ保存しない。
- Basic認証は外側の入口であり、アプリ内のロール認可を代替しない。認可は画面ではなくAPI層で検証する。
- `BASIC_AUTH_*` と `PBKDF2_ITERATIONS` は必須のWorker設定。未設定時は起動時に失敗させる。
- `input/`、`output/`、実際のOCR入出力、秘密値をコミットしない。
