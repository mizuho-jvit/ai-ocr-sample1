## Project Structure

```
src/
├── react-app/       # Vite + React SPA（11画面）
│   ├── pages/       # 画面単位のコンポーネント
│   ├── components/  # 共通UI
│   └── api/         # /api/* を叩くクライアント
└── worker/          # Hono on Workers
    ├── index.ts     # Basic認証ミドルウェア → ルーティング → ASSETS.fetch()
    ├── routes/      # /api/auth, /api/applications, /api/members, /api/staff, /api/ocr, /api/checks, /api/images
    ├── services/    # 業務ロジック（OCR Pipeline・業務チェック・名寄せ）
    ├── db/          # Drizzle スキーマ・クエリ
    └── types/       # SPA と共有する型（相対パスで import）
drizzle/             # D1 マイグレーション
knowledge/wiki/      # 要件の正典（実装対象ではない）
docs/dev/            # 実装計画・コンテキスト（本ファイル）
```

一体型のため、SPA から Worker 側の型を相対パス（`../../worker/types`）で直接 import する。
ただし **SPA から Worker の service 実装を import してはならない**。SPA は `fetch('/api/...')` のみで通信する。

## Coding Conventions

### Naming

| Target | Convention | Example |
|--------|-----------|---------|
| Variables | camelCase | applicationId |
| Functions | camelCase | findMemberCandidates |
| Classes/Types | PascalCase | ApplicationStatus |
| Files | kebab-case | ocr-pipeline.ts |
| Constants | UPPER_SNAKE | MAX_AI_CALLS_PER_MONTH |
| DB columns | snake_case（Drizzle スキーマ側でマッピング） | created_at |

すべて TypeScript の一般的な規約に基づく 🟡。

### Error Handling

- Hono の `onError` によるエラーミドルウェアで API のエラー応答を一元化する 🟡
- **認証エラーの文言はアカウント存在を推測させない**（F-1-7: 「メールまたはパスワードが違います」に統一）🔵
- Basic認証の資格情報・AIのペイロードを **エラー応答に含めない** 🔵

### Import Style

External → Internal（`src/worker/...`）→ Relative の順。named import を優先する 🟡

### Logging

- 開発時は `console.log`。Workers のログは `wrangler tail` で確認する 🟡
- **AI Gateway のログはメタデータのみ**。ペイロード（元画像を含む本文）の収集は無効化する（NF-2-42・AI-7a）🔵
- Basic認証の資格情報をログに出力しない（F-1-14）🔵

### 実装時に必ず守る技術制約（要件由来）

正典は wiki 側。ここには「コードを書く手が直接引っかかるもの」だけを転記する。

- **CPU時間 10ms/リクエスト**（無料枠）。ネットワーク待機はカウントされないため AI API の応答待ち（10〜15秒）は問題ない。
  計算処理はパスワードハッシュのみ注意（デモは `PBKDF2_ITERATIONS=20000`・NF-2-7）。`wrangler dev` では
  CPU制限が適用されないので、実測は `--remote` か本番デプロイ後（OP-6）
- **画像リサイズはクライアント側**（長辺1568px・JPEG品質85%）。Worker の CPU を使わない（F-2-2）
- **Workers Static Assets は Worker より先に静的ファイルを返す既定**。`assets.run_worker_first = true` を必ず設定し、
  全リクエストを Hono の Basic 認証ミドルウェアへ通す（F-1-13）
- **セッションは HTTPOnly / Secure / SameSite=Lax の Cookie + D1**。JWT を localStorage に保存してはならない（F-1-3・F-1-4）
- **ロール認可は API レベルで必ず検証する**。画面side だけの制御は不可（F-1-5）
- **Basic認証はロール認可を代替しない**（F-1-12）
- 環境変数の一覧と未設定時の起動失敗条件は [非機能要件](../../knowledge/wiki/requirements/non-functional.md) にある。
  `PBKDF2_ITERATIONS` 未設定・`BASIC_AUTH_*` 未設定では **起動させない**
