凡例: 🔵 正典に基づく確実なストーリー（🟡/🔴なし）。

## ペルソナ

### 職員（staff）

申請を読み取り、疑わしい箇所だけ確認して台帳を確定する利用者。

### 管理者（admin）

職員の権限管理とデモ環境のリセットも担う利用者。

## エピック1: 認証と業務入口

### US-001: 安全に職員としてログインする 🔵

私は職員として、Basic認証後にメールとパスワードでログイン/ログアウトしたい。そうすることで自分のロールに応じて業務を開始できる。

- 関連要件: FR-001, NFR-101, NFR-102 / 優先度: Must Have / 受入: AC-001

## エピック2: OCR・一次審査

### US-002: 申請書を読み取る 🔵

私は職員として、1枚の画像を選択・撮影・ドロップして帳票項目を抽出したい。そうすることで転記作業を減らせる。

- 関連要件: FR-002, FR-003, NFR-001, NFR-201 / 優先度: Must Have / 受入: AC-002, AC-003, AC-011

### US-003: AI業務チェック結果を確認する 🔵

私は職員として、矛盾、不備、名寄せ、トリアージ、差戻し下書きを確認したい。そうすることで疑わしい申請だけを審査できる。

- 関連要件: FR-004, NFR-103 / 優先度: Must Have / 受入: AC-004, AC-013

## エピック3: 申請と会員

### US-004: 申請を編集・判定する 🔵

私は職員として、抽出値を直し、チェックを再実施し、申請を承認または差戻ししたい。そうすることで最終判断を人間が行える。

- 関連要件: FR-005 / 優先度: Must Have / 受入: AC-005

### US-005: 会員台帳を維持する 🔵

私は職員として、会員を検索・登録・編集・状態変更し、履歴と重複疑いを確認したい。そうすることで台帳を正確に保てる。

- 関連要件: FR-006 / 優先度: Must Have / 受入: AC-006

### US-006: 名寄せを判断する 🔵

私は職員として、候補を比較して紐付け、別人、保留を選びたい。そうすることで同一人物の二重登録を防げる。

- 関連要件: FR-007, NFR-301 / 優先度: Must Have / 受入: AC-007, AC-015

## エピック4: 管理・入出力・リセット

### US-007: スタッフを管理する 🔵

私はadminとして、スタッフアカウントを登録・編集・無効化したい。そうすることで権限を管理できる。

- 関連要件: FR-008 / 優先度: Must Have / 受入: AC-008

### US-008: CSVで台帳を連携する 🔵

私は職員として、台帳を出力し会員名簿を取り込みたい。そうすることで既存業務とデータを交換できる。

- 関連要件: FR-009 / 優先度: Must Have / 受入: AC-009

### US-009: 商談前後にデモを初期化する 🔵

私はadminとして、確認語を入力してデモデータをリセットしたい。そうすることで次の商談へ安全に引き渡せる。

- 関連要件: FR-010, NFR-103, CON-001 / 優先度: Must Have / 受入: AC-010, AC-013, AC-016

### US-010: テナント境界を守る 🔵

私は職員として、自テナントのデータだけを見て操作したい。そうすることで共有デモ環境でも他組織の情報を開示しない。

- 関連要件: NFR-301 / 優先度: Must Have / 受入: AC-015

## ユーザージャーニー

`US-001 → US-002 → US-003 → US-006 → US-004`（ログイン→読取→チェック→名寄せ→人手承認）
